# 05. Диагностика, Big O и метрики

Анализ полностью детерминированный (без LLM, см. ADR-03). Каждая находка содержит всё, что слайд 5 требует показать участнику: строку кода, узел графа, объяснение, оценку сложности, вариант исправления с ожидаемым эффектом.

## 1. Что получает пользователь

```
Находка (Finding)
├── id, rule_id, severity (Высокая/Средняя/Низкая), category (PERF/BUG/MAINT)
├── title        «Вложенный цикл — O(n²)»
├── location     файл, строки, node_id, method_id          ← «строка кода и узел графа»
├── explanation  что происходит, почему плохо              ← «объяснение»
├── complexity   «O(n²)», цепочка вкладов                  ← «оценка сложности»
├── risk         «Рост времени при увеличении входа»
├── evidence     статические факты + динамические проверки ← «проверяемость»
└── fix          рекомендация, fix_id, ожидаемый эффект    ← «вариант исправления с эффектом»
```

Соответствие макету (правая панель «Анализ»): вкладки **Проблемы (N)** — список находок с важностью и ссылкой `Файл.java:строка`; **Рекомендации (N)** — исправления по находкам; **Метрики** — LOC, цикломатика, вложенность, покрытие; блок **Сложность** — «Текущая O(n²) → После оптимизации O(n log n)»; блок **Оценка производительности** — «Ожидаемое ускорение до 5.2×» (измеренное, см. раздел 9).

```
Semantic model ─► Cost model ─► Method complexity ─┐
        │                                          ├─► Rules ─► Findings ─► Fix proposals
```

## 3. Модель стоимости (Big O)

### 3.1 Основа

Размер входа `n` — **один обобщённый параметр** (допущение из [01 § 10](01-requirements.md#10-допущения)). Стоимость выражается как многочлен от `n` и `log n` с целыми степенями: `O(1)`, `O(log n)`, `O(n)`, `O(n log n)`, `O(n²)`, `O(n² log n)`, `O(n³)`, `O(2ⁿ)` (рекурсия). Компактное представление: пара `(степень n, степень log n)` + флаг «экспоненциальная».

Символьные размеры: каждая коллекция, массив, строка и диапазон имеют **источник размера**. Это либо `n` (производный от ввода — вход метода или данные, считанные из `System.in`), либо константа (литерал, `Map.of(…)` из 3 элементов, константный `for (i < 10)`).

### 3.2 Правила вычисления

| Конструкция | Стоимость |
|---|---|
| Оператор, выражение без вызовов | O(1) |
| Последовательность `A; B` | `A + B` → доминирующая |
| `if/else` | `cond + max(then, else)` |
| `switch` | `max(case)` |
| `for (init; cond; update)` | `число итераций × (тело + cond + update)`; число итераций — по эвристике (3.3) |
| `for each` по коллекции размера `s` | `s × тело` |
| `while` / `do-while` | Как `for`: число итераций выводится по паттерну счётчика или `hasNext/ read`; иначе принимается `n` и ставится метка «оценка» |
| `break`/`return` в цикле | Худший случай не уменьшается; помечается «возможен ранний выход» |
| Вызов метода проекта | Стоимость метода (мемоизация); для перегрузок — максимум |
| Рекурсия | Паттерны: одна рекурсия с `n−1` → O(n) (× стоимость шага); с `n/2` → O(log n) (× шаг) или O(n) если шаг O(n); две рекурсии с `n−1` → O(2ⁿ); иначе — «оценка неизвестна, принимаем O(n)» |
| Вызов JDK | Каталог стоимости (3.4) |
| Лямбда, передаваемая в метод JDK | `вызовы × стоимость тела`, число вызовов — по методу потребителю (`forEach`, `removeIf`, `map`: n) |
| Stream | Сумма стоимостей этапов; ленивые этапы с `limit`/`anyMatch` помечены «возможно сокращение» |
| Вывод `println` | O(1) на вызов (но правило `IO_IN_LOOP` отдельно) |

### 3.3 Число итераций цикла

Паттерны, распознаваемые для `for` и `while`:

| Паттерн | Итерации |
|---|---|
| `for (i = a; i < N; i++)` / `i--` / `i += k` (k константа) | `(N − a)/k`: размер `N` определяет источник (длина коллекции/массива, параметр = `n`, константа → O(1)) |
| `for (i = 1; i < N; i *= 2)` / `i /= 2` | O(log N) |
| `for (i = 0; i < a.length; i++)` | размер массива `a` |
| `for (i = 0; i < list.size(); i++)` | размер списка |
| `for (i = 0; i < j; i++)` во вложенном цикле, `j` — счётчик внешнего | O(n) (треугольный), общее ≈ n²/2 → O(n²) |
| `for (j = i + 1; j < n; j++)` | O(n) (треугольный) |
| `while (it.hasNext())`, `while (sc.hasNext())` | размер источника (`n`) |
| `while (lo <= hi)` с делением диапазона пополам | O(log n) |
| `while (cond)` без распознанного паттерна | `n`, метка «эвристика» |

Для «эвристических» оценок в находке указывается уровень уверенности (`exact`/`heuristic`) и причина. Это часть проверяемости диагноза: пользователю честно показывается, где оценка не строгая.

```json
{

  "complexity": "O(n²)",
  "confidence": "exact",
  "contributions": [
```

## 4. Метрики

| Метрика | Определение |
|---|---|
| LOC (всего, на метод, на класс) | Непустые строки без комментариев |
| Цикломатическая сложность (метод) | 1 + число `if`, `case`, циклов, `catch`, `&&`, `||`, `?:` |
| Максимальная вложенность | Глубина вложенных операторов в методе |
| Число параметров, число локальных переменных | Простые счётчики |
| Связность класса (LCOM4) | Число компонент связности в графе «методы — используемые поля» |
| Эффективная сложность по Big O | Максимум по методам (отображается как «Текущая») |
| Покрытие узлов | Узлы, выполненные сценариями (из трассировки) / все узлы |
| «Здоровье» | Сводная оценка 0–100 для заголовка вкладки; формула документирована в коде (сумма штрафов по находкам с весами важности) |

Метрики считаются для версии и сравниваются «до/после» (строка «Оригинал → Текущая»).

## 5. Каталог правил

Идентификатор правила: `CATEGORY-NN`. Важность — `high`/`medium`/`low`; в макете: Высокая / Средняя / Низкая. Пороги настраиваются в `project.settings`.

### 5.1 Производительность (PERF)

| ID | Правило | Условие срабатывания | Исправление (fix_id) | Ожидаемый эффект |
|---|---|---|---|---|
| PERF-01 | **Вложенный цикл поиска/слияния** — O(n²) | Внутренний цикл по коллекции того же размера содержит `equals`/сравнение ключа элементов двух коллекций | `OPT-01` индексировать `Map` по ключу | O(n²) → O(n) |
| PERF-02 | **Линейный поиск в цикле** | `list.contains(x)`, `indexOf`, `remove(Object)` в цикле по `n` | `OPT-02` `contains` по `ArrayList` → `HashSet` | O(n²) → O(n) |
| PERF-03 | **Конкатенация строк в цикле** | `s += …` / `s = s + …` в цикле | `OPT-03` `StringBuilder` | O(n²) → O(n) |
| PERF-04 | **Сортировка внутри цикла** | `sort` на каждой итерации | `OPT-04` вынести сортировку из цикла (при инвариантности коллекции) | O(n² log n) → O(n log n) |
| PERF-05 | **Инвариант в цикле** | Вызов с неизменной коллекцией/значением (`list.size()` для `LinkedList`, `map.keySet().size()`, `str.length()` вычисляется O(n)) | `OPT-05` вынести в переменную | Снижение степени/константы |
| PERF-06 | **Неподходящая коллекция** | `LinkedList.get(i)` в цикле; `ArrayList.add(0, …)` в цикле | `OPT-06` `LinkedList` → `ArrayList` / `ArrayDeque` | O(n²) → O(n) |
| PERF-07 | **Повторное вычисление** | Одно и то же чистое выражение или вызов дважды с теми же аргументами | `OPT-07` выделить переменную | константа |
| PERF-08 | **Рекурсия без мемоизации** | Двойная рекурсия `f(n−1)`/`f(n−2)`, чистая | `OPT-08` мемоизация через `HashMap` | O(2ⁿ) → O(n) |
| PERF-09 | **Ручной обход там, где есть готовый** | Ручной вложенный `for` для подсчёта частот, группировки | `OPT-09` `HashMap.merge` / `Collectors.groupingBy` | O(n²) → O(n) |
| PERF-10 | **Ввод-вывод в цикле** | `System.out.println` в цикле большого размера без буфера | `OPT-10` накопление в `StringBuilder` + один вывод (только при отсутствии чередования с ошибками stderr и вводом) | константа ×k |
| PERF-11 | **Лишняя работа в стриме** | `sorted` перед `filter`; `collect` и затем `stream` по результату | `OPT-11` переставить этапы | константа |
| PERF-12 | **Лишнее боксирование в горячем цикле** | `Integer`/`Long` в цикле счётчика, накопление в обёртке | `OPT-12` примитив | константа |
| PERF-13 | **Поиск по ключу перебором в методе, вызываемом из цикла** | Метод вида `T find(K key)`: перебор `private`-поля `List<T>` и `return null`; вызывается (прямо или по цепочке вызовов) из цикла с неконстантным числом итераций | `OPT-13` индекс `Map`, который ведётся вместе со списком | O(n²) → O(n) |

### 5.4 Пример срабатывания (слайд 5)

Код:

```java
for (Item a : items) {
    for (Item b : items) {
        if (a.id().equals(b.id())) {
            merge(a, b);
        }
    }
}
```

Находка `PERF-01`:

| Поле | Значение |
|---|---|
| Заголовок | Вложенный цикл — O(n²) |
| Место | `Analyzer.java:42-48`, узел `for[0]/for[0]` |
| Объяснение | Внешний и внутренний циклы обходят `items`; условие сравнивает `id` двух элементов, поэтому каждая пара обрабатывается дважды, а число сравнений растёт как n² |
| Дефект | Повторная обработка одинаковых пар |
| Риск | Рост времени при увеличении входа |
| Рекомендация | Индексировать элементы по `id` |
| Исправление | `OPT-01`: `Map<Id, Item> byId = new HashMap<>(); for (Item a : items) { Item b = byId.putIfAbsent(a.id(), a); if (b != null) merge(b, a); }` — применимо, если `merge` не читает порядок элементов. Предусловия показываются пользователю |
| Эффект | O(n²) → O(n); измеренное ускорение — после «Проверить» |

## 6. Как правила находят паттерны

- Правила работают **по семантической модели**, а не по тексту: тип выражения (`String`, `List`), источник размера, чистота вызова, инвариантность выражения в цикле.
- Каждое правило — класс `Rule` с методами `detect(model) -> list[Match]` и `explain(match) -> Explanation`; для исправляемых — `fix(match) -> FixProposal | None`.
- Объяснения собираются из шаблонов с подстановкой фактов: имена переменных, строки, размеры, цепочка вкладов.
- Дедупликация: одна находка на узел и правило; родительские циклы не порождают дубли.
- Порядок в списке: важность, затем сложность, затем строка.

## 7. Инвариантность и чистота (для безопасных исправлений)

Автоисправления `OPT-*` опираются на проверки из семантической модели:

| Проверка | Реализация |
|---|---|
| Выражение инвариантно в цикле | Нет записи в зависимые переменные в теле, нет вызовов нечистых методов, нет изменения использованной коллекции |
| Метод чист | Не пишет поля, не вызывает ввод-вывод, не вызывает нечистые методы (транзитивно), не принимает изменяемые аргументы, которые меняет |
| Коллекция не изменяется | Нет `add/remove/put/clear/set` по этой переменной в области; она не передаётся в нечистые методы |
| Порядок итерации не важен | Результат цикла не зависит от порядка: тело использует только накопление через коммутативные операции |
| Нет алиасинга | Переменная не присваивается другой переменной-коллекции (консервативно) |

Если проверка не пройдена — находка остаётся, но кнопка исправления заменяется рекомендацией и причиной («метод merge пишет в поле — порядок существенен»).

## 8. Связь находок с графом и кодом

- Находка → маркер в Monaco (`setModelMarkers`, волнистая линия) и бейдж ⚠ на узле графа (как красный/жёлтый значок на блоках «Условие» и «Метод» в макете). Клик по находке в списке выделяет узел и строки.
- Диапазон находки — оператор целиком; для PERF — заголовок цикла (чтобы не перекрывать блок).
- Фильтры в списке: важность, категория, файл, «только исправляемые».

## 9. Оценка ускорения

Показатель «Ожидаемое ускорение до N×» — **измеренный**, а не теоретический:

1. Для версии берутся сценарии `scaled` (масштабируемые входы, см. [07 § 8](07-behavior-verification.md#8-бенчмарк-и-эмпирическая-сложность)) на 3–4 размерах.
2. Запускаются «Оригинал/до» и «После» по 3 раза, берётся медиана времени.
3. Ускорение = `time(before) / time(after)` на наибольшем размере; значение «до 5.2×» — максимум по размерам.
4. Если масштабируемых сценариев нет, показывается теоретическая оценка (`O(n²) → O(n)`) без числа, с пометкой «не измерено».

## 10. Проверяемость диагноза

Требование слайда 5: «Диагноз должен быть проверяемым, а не только красивым». Для каждой находки PERF доступны три уровня доказательств:

| Уровень | Что | Где показывается |
|---|---|---|
| **Статический** | Цепочка вкладов Big O: какие циклы и вызовы дают n × n; какие факты использованы (тип, размер, чистота) | Карточка находки, «Почему» |
| **Динамический: счётчики** | Трассировка (`JbTrace`) считает выполнения узлов: цикл N раз, тело N² раз для входа размера N. Наложение на граф (Дебаг) | Кнопка «Проверить» → счётчики на узлах |
| **Эмпирический рост** | Время и счётчики для входов размером N, 2N, 4N, 8N; log-log регрессия даёт показатель роста (`k ≈ 1.97` → O(n²)) | График в карточке: «Предсказано O(n²) — измерено k=1.97» |

Для дефектов BUG доступен **сценарий-воспроизведение**: генератор ищет вход, на котором проявляется проблема (исключение, неверный вывод), и привязывает его к находке. Если вход не найден, находка помечается «не подтверждена динамически» — честно, без скрытия.

Расхождение статической и эмпирической оценок больше порога (±0,5 степени) подсвечивается предупреждением: оценка может быть неточной (например, ранний выход из цикла).

## 11. Ограничения

- Оценка зависит от допущения «один параметр n»; многопараметрические зависимости (`n × m`) схлопываются в `n²` с пометкой «два размера».
- Неизвестные методы JDK принимаются за O(1) (помечается).
- Правила BUG-04/05/06/11 опираются на упрощённый вывод типов и могут давать ложные срабатывания. Для них задана низкая важность и пометка «эвристика».
- Интерпроцедурный анализ — в пределах проекта; динамическая диспетчеризация учитывается по всем реализациям (консервативно).
