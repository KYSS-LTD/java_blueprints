# Java Blueprints — документация

Веб-инструмент показывает Java-монолит одновременно как код и как граф (блок-схему). Он находит дефекты и узкие места по сложности (Big O) и помогает улучшить программу: оптимизировать, разбить на классы, поправить блоки. После каждого изменения инструмент сам доказывает, что поведение программы осталось прежним.

Кейс: AXENIX, 48-часовой хакатон «Визуальная среда программирования Java Blueprints».

## Ключевые решения

- **Стек:** backend — Python 3.12 + FastAPI, frontend — Next.js (App Router) + TypeScript + shadcn/ui + Tailwind CSS.
- **Разбор Java:** tree-sitter-java через py-tree-sitter, прямо в Python-бэкенде. Код из графа получается точечными правками текста по диапазонам синтаксического дерева.
- **Источник истины — текст Java.** Граф всегда вычисляется из кода. Правка графа — это операция, которая превращается в правку текста.
- **Без LLM.** Диагностика, оптимизации, генерация сценариев и декомпозиция работают на детерминированных алгоритмах: при одинаковом входе результат всегда один и тот же.
- **Хранение:** SQLite через SQLModel.
- **Проверка поведения (golden master):** каждый сценарий запускается на исходной и на изменённой версии, затем сравниваются нормализованные stdout, stderr и код выхода. Сценарии можно написать вручную, импортировать или сгенерировать: инструмент выводит формат ввода и мутирует его, ориентируясь на покрытие узлов графа.
- **Запуск Java:** JDK 21 (Eclipse Temurin) в контейнере бэкенда; `javac` и `java` работают как подпроцессы с таймаутами и лимитами.
- **Граф во фронтенде:** React Flow (`@xyflow/react`) + ELK (`elkjs`) для автоматической раскладки с вложенными контейнерами. Редактор кода — Monaco.

Обоснование каждого решения — в [03-tech-stack.md](03-tech-stack.md#5-принятые-решения-adr).

## Глоссарий

| Термин | Значение |
|---|---|
| Монолит | Исходная Java-программа (~1000 строк, обычно один большой класс), загружаемая в инструмент |
| Версия | Снимок всех файлов проекта. Версия 1 — «Оригинал». HEAD — текущая версия |
| Граф структуры | Граф классов, интерфейсов, record, enum, их полей и методов и связей между ними (наследование, вызовы, использование) |
| Блок-схема | Граф управления одного метода: узлы-блоки (переменная, условие, цикл…) и рёбра переходов |
| Блок / узел | Элемент блок-схемы, соответствует оператору Java |
| Операция над графом | Команда изменения графа (вставить, изменить, удалить, переместить блок…), которую backend превращает в правку текста |
| Сценарий | Входные данные одного запуска программы: stdin и аргументы командной строки |
| Эталон (baseline, golden master) | Нормализованный результат запуска сценария на эталонной версии (по умолчанию — «Оригинал») |
| Quality gate | Синтаксическая проверка + компиляция + прогон всех сценариев с совпадением с эталоном |
| Находка (finding) | Результат диагностики: проблема, место (строка и узел), объяснение, сложность, рекомендация, ожидаемый эффект |
| Автоисправление (autofix) | Преобразование кода, которое инструмент применяет сам при выполнении проверяемых предусловий |
| Трассировка | Запуск инструментированной программы с подсчётом выполнений каждого узла (кнопка «Дебаг» в макете) |
| Покрытие | Доля узлов блок-схем, выполненных хотя бы одним сценарием |
