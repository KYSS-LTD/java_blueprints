# S5. Двусторонняя правка: граф ↔ код

**Часы:** H16–28 · **Треки:** A (engine), B (API), C (UI) · **Веха:** M1 (S5.1), M2 (остальное) · **Требования:** FR-06, FR-07, FR-08

## Цель

Сделать граф редактируемым: операции над блоками превращаются в точечные правки Java-текста, а правка кода мгновенно обновляет граф. Ввести версии с undo/redo.

## Зависимости

S2 (граф, ID, диапазоны), S3 (версии, файлы), S4 (холст, Monaco, дерево).

### Как устроена правка на frontend

- **Слот вставки определяется по структурному id блока**, а не по `parent_id`: ветки `if` в схеме не контейнеры, и операторы `then`/`else` числятся за ближайшим циклом, `try` или `catch` (`lib/edit/slots.ts`). Перемещение внутрь самого себя отсекается сравнением префиксов id.
- **Все изменения проекта идут по очереди** (`lib/edit/session.ts`): каждое читает актуальный HEAD в момент запуска, поэтому `base_version_id` не устаревает от собственных запросов. Правки кода схлопываются backend'ом в ту же версию, поэтому после любого изменения версионные данные (`tree`, `file`, `flow`, `structure`) инвалидируются независимо от номера версии, а то, что клиент знает сам (текст сохранённого файла, схема из ответа `ops`), кладётся в кеш новой версии без перечитывания.
- **Состояние правки** — `stores/editor-store.ts`: черновики файлов, ошибки живого разбора, последняя корректная схема метода, состояние сохранения, счётчик «занято» (редактор только для чтения, пока идёт операция), открытый инспектор.
- Клавиши холста обрабатываются, только если событие пришло из самого холста: меню и диалоги рисуются порталом, но события React всплывают через него.

### Найдено при проверке в браузере

- Единица отступа в `engine/edit/core.py` определялась по минимальному положительному отступу, и строки ` * …` javadoc (отступ в 1 пробел) давали единицу в 1 пробел: `wrap_node` сдвигал тело на 1 пробел. Продолжения блочных комментариев теперь пропускаются.
