# S4. Frontend: рабочая область и граф

**Часы:** H10–24 · **Трек:** C (Frontend) · **Веха:** M1 · **Требования:** FR-01, FR-03, FR-04, FR-05, FR-10

## Цель

Собрать интерфейс по концепт-макету: шапка, дерево проекта и палитра, холст графа, редактор кода, консоль, панели результатов. Показать на холсте блок-схемы (в том числе контейнеры циклов и ветки Да/Нет), связать их с кодом в обе стороны **для чтения** (правка — S5).

## Зависимости

S0.4–S0.5, S1.2 (моки). Реальные эндпоинты S3 подключаются по мере готовности: сначала импорт и дерево, затем граф и запуск.

Решения:

- **ELK без `INCLUDE_CHILDREN`.** Каждый контейнер раскладывается отдельно (`SEPARATE_CHILDREN`), а ребро между блоками разных уровней поднимается до пары соседей под общим предком. Это позволяет раскладывать `switch` сеткой (`box`) — иначе 22 ветки без связей выстраиваются в одну линию — и не зависит от того, как ELK обрабатывает рёбра «контейнер → свой потомок». Рёбра рисует React Flow по координатам блоков.
- **Рёбра «контейнер → содержимое» (`body`, `case`, `exception`) не рисуются:** их выражает вложенность; тип исключения у `catch` показан в заголовке.
- **`ELK` в браузере подключается через `elk-api` и `workerFactory`**, а не через `elk.bundled.js`: на бандле `new ELK()` в браузере падает (`_Worker is not a constructor`). В Node (тесты) используется бандл.
- Вкладок-файлов в центре нет: файл метода показывает панель «Код Java» (`activeFile`), список файлов — дерево проекта.
- Граф структуры берёт один запрос `mode=methods` и строит «Типы» фильтром: в ответе `mode=types` нет членов, а число членов нужно карточке.
- Правка графа и кода — S5: Monaco и холст только читают.
