# 09. Frontend

Next.js (App Router) + TypeScript + shadcn/ui + Tailwind. Интерфейс на русском, тёмная тема, раскладка — по концепт-макету (слайд 4: «Визуальная среда программирования»).

## 3. Компоненты по зонам

### 3.1 Шапка

| Элемент | Действие |
|---|---|
| «Импорт Java» | Диалог импорта: добавить файлы/архив в проект или заменить версию (создаёт версию) |
| «Экспорт Java» | Меню: файл/архив версии (HEAD или любая), отчёт, bundle |
| «Оптимизировать» | Диалог плана оптимизации (шаги, эффект, галочки) → пошаговое применение со статусами gate |
| «Запуск» | Выпадающая кнопка: запустить (диалог stdin/args, сценарий из списка) / сохранить как сценарий. Результат — в «Консоли» |
| «Дебаг» | Трассировка выбранного сценария; включает оверлей счётчиков на графе |
| Индикатор версии | `v13 · Оптимизация O(n²)→O(n)` · undo/redo · кнопка «История» (Sheet с версиями и diff) |
| Статус поведения | Бейдж: «✓ поведение совпадает (12/12)» / «✗ расхождение (2)» / «? не проверено» — клик открывает «Результат тестов» |
| ⚙ | Настройки проекта: таймауты, пороги правил, главный класс, локаль |

### 3.2 Левая колонка

**Проект** — дерево (`Collapsible`/кастомный Tree): пакеты → файлы → типы → члены. Иконки по типам, бейджи находок (красный/жёлтый кружок), метрика сложности у метода. Клик по методу — открыть схему; контекстное меню (`ContextMenu`): переименовать, удалить, выделить в метод, показать в графе структуры.

**Блоки** — палитра (Переменная, Условие, Цикл, Метод, Операция, Возврат + Присваивание, Switch, Try/catch, Throw, Break/Continue): поиск «Поиск блоков…», перетаскивание на холст (HTML5 drag → React Flow `onDrop`) либо клик по блоку — вставка после выделенного узла. После сброса открывается инспектор с полями шаблона (см. [04 § 5.4](04-code-graph-model.md#54-шаблоны-генерации-блоков)).

### 3.3 Центральная область

**Вкладки:** открытые методы/файлы + «Структура» (граф типов). Закрепление, закрытие.

**Холст графа** (`@xyflow/react`):

- Кастомные узлы по `kind` (цвета и иконки как в макете: фиолетовый «Метод», синий «Переменная», оранжевый «Условие», зелёный «Возврат», бирюзовый «Операция»/«Цикл»);
- Рёбра: сплошные, ветки `Да`/`Нет` в «пилюлях», жёлтый пунктир — внешний вызов;
- Контейнеры цикла/try/switch с заголовком и сворачиванием;
- Бейджи на узле: ⚠ находка, `O(n²)`, «вывод», «ввод», число выполнений (Дебаг);
- Панель управления: масштаб `−/+`, «вписать» (`⛶`), мини-карта, переключатель оверлеев (находки / сложность / покрытие / вызовы);
- Раскладка ELK (`layered`, направление вниз) в Web Worker; повторная раскладка при структурных изменениях, позиции сохраняются между небольшими правками. Реализовано как `elk.hierarchyHandling: SEPARATE_CHILDREN`: каждый контейнер раскладывается отдельно, ребро между блоками разных уровней поднимается до пары соседей под общим предком, а ветки `switch` упаковываются сеткой (`box`), потому что между ветками нет рёбер. Подробности — [plan/s4](plan/s4-frontend-workspace.md#статус-выполнения);
- Выделение: клик, Shift+клик (подряд идущие блоки одного слота от опорного блока), Ctrl/Cmd+клик (добавить блок к выбору или убрать) → панель «Выбрано блоков: N» над холстом с действием «Выделить в метод»; Escape сводит выбор к последнему блоку. Рамка мышью не реализована. Delete, Ctrl+D и Enter при выборе нескольких блоков не действуют.

**Редактирование на холсте:**

| Жест | Результат |
|---|---|
| Перетащить блок из палитры на ребро/слот | `insert_node` |
| Двойной клик по блоку / «Править» | Инспектор (форма по `kind`) → `update_node` |
| Перетащить блок на другое место | `move_node` (проверка областей видимости; подсветка допустимых слотов) |
| `Delete` | `delete_node` (контейнер — диалог: «с телом» / «оставить тело») |
| `Ctrl+D` | `duplicate_node` |
| Кнопка «+ ветка» на условии/try/switch | `add_branch` |
| Контекстное меню блока | Обернуть, развернуть, выделить в метод, показать код, показать находки |
| `Ctrl+Z / Ctrl+Shift+Z` | undo / redo версий (весь проект) |

После каждой операции: ответ сервера обновляет код в Monaco (изменённый диапазон подсвечивается на 1,5 с) и схему; фокус — на `focus_node_id`. Ошибки (`INVALID_FRAGMENT`, `409`) показываются в форме и тостом, граф не меняется.

Как это реализовано (подробности — [plan/s5](plan/s5-editing.md#статус-выполнения)):

- перетаскивание — HTML5 drag-and-drop, а не перетаскивание узлов React Flow: блок схемы тянут целиком, контейнер — за заголовок; над блоком подсвечивается место (полоса сверху или снизу, для контейнера — рамка), на пустое место холста блок из палитры попадает в конец метода;
- контекстное меню открывается правой кнопкой по блоку; блокам `catch`, `finally`, `switch` доступны свои действия, `try` и методу форма не предлагается — они правятся в коде;
- вся правка проходит через одну очередь запросов проекта, а пока выполняется операция, редактор кода доступен только для чтения.

### 3.4 Инспектор узла

Панель справа от холста, поверх неё (не модальная: холст остаётся доступным). Форма (`react-hook-form` + zod) по виду блока; живая валидация через `POST /validate/expression`; предпросмотр кода, который будет вставлен; кнопка «Применить». Для блока «Код» — Monaco-мини с произвольным текстом (`replace_code`). Вкладка «Анализ узла»: оценка сложности фрагмента, цепочка вкладов, находки по узлу.

### 3.5 Нижние панели

| Панель | Содержимое |
|---|---|
| **Код Java** | Monaco: подсветка Java, нумерация, маркеры находок (волнистая линия) и ошибок компиляции, декорация выделенного узла; режимы «Код» / «Diff с оригиналом» / «Diff с версией…»; кнопка «Сохранить» (Ctrl+S) и автосохранение через паузу |
| **Консоль** | Журнал: сборка (зелёные «Компиляция успешна ✓»), запуск, stdout/stderr (разные цвета), код выхода, время. Поле stdin (многострочное) и аргументы. Кнопка очистки |
| **Результат тестов** | Заголовок «Все тесты пройдены — 12 из 12», прогресс-бар, таблица «Тест / Результат / Время»; клик по строке — diff вывода; кнопки «Запустить тесты», «Сгенерировать сценарии», «Записать эталон», «Экспорт отчёта»; покрытие узлов в процентах; блок управления сценариями (добавить/изменить/отключить) |

### 3.6 Правая колонка «Анализ»

Вкладки `Проблемы (N)`, `Рекомендации (N)`, `Метрики`:

- **Проблемы** — карточки: иконка важности, заголовок («Длинный метод»), бейдж («Высокая»/«Средняя»/«Низкая»), `Файл.java:строка`, объяснение; клик — выделение в графе и коде; раскрытие — «Почему» (цепочка вкладов), «Проверить» (динамические доказательства), «Исправить».
- **Рекомендации** — те же находки с готовыми исправлениями: предпросмотр diff + эффект + предусловия, «Применить» (с gate).
- **Метрики** — LOC, цикломатика, вложенность, LCOM4, покрытие; «Оригинал → Текущая».
- **Сложность** (под вкладками, как в макете): `Текущая: O(n²)` → `После оптимизации: O(n log n)`.
- **Оценка производительности:** «Ожидаемое ускорение: до 5.2×» (измеренное, ссылка на график бенчмарка) либо «не измерено».
- Фильтры: важность, категория, файл.

Как это реализовано (подробности — [plan/s7](plan/s7-analysis.md#статус-выполнения), [plan/s8](plan/s8-optimization.md#статус-выполнения)):

- карточки и их части лежат в `components/analysis/*`, панель — `components/workspace/analysis-panel.tsx`, чистая логика (фильтры, разбор итогов запусков `verify` и `optimize`, маркеры, метрики) — `lib/analysis/*`;
- **«Проверить»** запускает `kind=verify` и следит за ним по SSE; итог (показатель роста k, график, предупреждения, у BUG/MAINT — «выполняется в N из M сценариев») остаётся в карточке и после перезагрузки (`evidence.dynamic`);
- исправление без доступного применения показывает не выполненные предусловия с причиной, кнопки «Предпросмотр» у него нет;
- «Оценка производительности» берёт измеренное ускорение из последнего завершённого запуска `optimize`, но только если он закончился на текущей версии: после отката или правки прежнее измерение к программе не относится;
- находки подчёркиваются в Monaco волнистой линией под первой строкой (оверлей «Находки» их выключает).

### 3.7 Диалоги и панели

| Компонент | Содержимое |
|---|---|
| Оптимизация | Шаги (галочки, у каждого метод и сложность «до → после») → статусы шагов по SSE → отчёт: применено N из M, пропущенные с причиной, статус поведения, измеренное ускорение и график «до/после», «Откатить всё» |
| Предпросмотр исправления | Diff в Monaco (неизменные области свёрнуты), предусловия (✓/✗), эффект; «Применить» ведёт к стадиям gate, а при красном gate у исправления, меняющего поведение, — к выбору «Принять» (затем «Записать эталон по новой версии») или «Отклонить» |
| Выделить в метод | Открывается из контекстного меню блока, панели выбранных блоков, контекстного меню Monaco (и Ctrl+Alt+M) над выделенным фрагментом и карточек находок MAINT-01/08. Поле «Имя метода» (предпросмотр обновляется через 350 мс), сигнатура, предусловия (✓/✗), предупреждения, diff; «Выделить метод» ведёт к стадиям gate (как у исправления). Если выделить нельзя, причина видна в предусловиях, а кнопка закрыта |
| Декомпозиция | Вкладка в центре: слева «До» (имя ядра, строки, члены, LCOM4), справа «После» (метрики, предупреждения, карточки классов с методами, связи между классами, типы в отдельных файлах); кнопка «Применить…» |
| История версий | Список версий с origin/описанием/статусом gate; «Сравнить с оригиналом», «Восстановить» |
| Результат gate | Стадии (syntax → compile → сценарии), diff упавших |
| Бенчмарк | Графики времени «до/после» (shadcn Chart), показатель роста k |
| Импорт | Dropzone, вставка текста, примеры |

Как это реализовано для выделения метода и декомпозиции (подробности — [plan/s9](plan/s9-extract-decompose.md#статус-выполнения)):

- применение версии-кандидата (запуск, стадии gate, «принять»/«отклонить» при красном gate, запись нового эталона) вынесено в `components/workspace/candidate-run.tsx` и общее для диалогов «Исправление», «Выделить в метод» и «Применить декомпозицию»;
- диалог выделения метода один на рабочую область (`ExtractDialog`), его открывает `workspaceStore.openExtract({ nodeIds } | { range })`; перед первым предпросмотром набранный код сохраняется, чтобы диапазон относился к текущей версии;
- вкладка «Декомпозиция» (`components/decompose/*`): автоматический план строится один раз на версию и параметр «Максимум новых классов»; каждая правка (перенос метода перетаскиванием или меню «Перенести в…», «Новый класс», переименование, схлопывание опустевшего класса) показывается сразу, а строки, связи и предупреждения приходят из `decompose/rescore`; отказ сервера возвращает прежний состав с причиной в тосте. Закреплённые члены (`pinned`) нельзя тянуть; ядро и вынесенные типы не переименовываются;
- применяется план в том виде, каким он был в момент нажатия «Применить…»: после успеха версия сменится, и вкладка построит новый план.

## 4. Синхронизация граф ↔ код

| Событие | Реакция |
|---|---|
| Клик по узлу | Monaco: `revealRangeInCenter` + декорация диапазона узла |
| Курсор в Monaco (дебаунс 150 мс) | `GET /locate` (или локальный индекс диапазонов из `FlowGraph`) → выделение узла на холсте и панорама к нему |
| Правка кода (пауза 400 мс) | `POST /parse` → обновить схему метода; ошибки — баннер над холстом «Синтаксическая ошибка в строке N», граф остаётся прежним и блокируется |
| Сохранение кода (пауза 800 мс / Ctrl+S) | `PUT /files/{path}` → новая версия, обновление дерева и анализа |
| Операция над графом | Ответ `ops` → заменить текст файла в Monaco (без сброса курсора, через `executeEdits`), обновить схему |
| Выбор находки | Выделение узла + маркер в коде + раскрытие карточки |
| Клик по «Метод (внешний вызов)» | Открыть схему вызываемого метода во вкладке |

Конфликты: пока идёт запрос `PUT`/`ops`, ввод в Monaco не блокируется; ответ с большим номером версии применяется, ответ с устаревшей `base_version_id` → повтор после обновления HEAD.

## 5. Состояние

| Хранилище | Что |
|---|---|
| TanStack Query | Серверные данные: проект, дерево, структура, схемы методов, находки, сценарии, запуски, версии; ключи содержат `projectId` и `versionId` |
| Zustand (`workspaceStore`) | Активный файл/метод/узел, выделенные узлы, открытые вкладки, режим холста, оверлеи, активная вкладка нижней/правой панели |
| Zustand (`editorStore`) | Несохранённый текст Monaco, позиция курсора, подсветки |
| `localStorage` | Размеры панелей, последний открытый проект, настройки отображения |
| SSE (`useRunEvents(runId)`) | Хук на `EventSource`: события сворачиваются в состояние запуска |

Инвалидация: после `ops` / `PUT files` / `apply` — инвалидируются `tree`, `flow`, `structure`, `analysis`, `versions`; статус gate обновляется по событию `result`.

## 6. Дизайн-система

- shadcn/ui, тема `dark` по умолчанию (переключатель светлой темы — на выбор после MVP, не в MVP).
- Токены цвета блоков как переменные CSS (`--node-method`, `--node-variable`, `--node-condition`, `--node-loop`, `--node-return`, `--node-operation`, `--node-call`), палитра взята из макета.
- Важность: Высокая — красный, Средняя — жёлтый/оранжевый, Низкая — синий/серый (бейджи `Badge`).
- Шрифты: Inter (UI), JetBrains Mono (код).
- Доступность: фокус-кольца, `aria-label` на иконочных кнопках, клавиатурная навигация по палитре и дереву, контраст AA для текста.

## 7. Тексты интерфейса

Все строки — в `src/lib/i18n/ru.ts` (один язык в MVP, но без «зашитых» строк в JSX). Заголовки блоков совпадают с макетом: «Метод», «Переменная», «Условие», «Цикл (for each)», «Операция», «Возврат», «Продолжить».

## 8. Производительность интерфейса

- Раскладка ELK — в Web Worker (не блокирует UI); для схем > 150 узлов — автосвёртка контейнеров глубже 3-го уровня.
- Узлы React Flow мемоизируются (`React.memo`); `onlyRenderVisibleElements`.
- Monaco загружается динамически (`next/dynamic`, `ssr: false`) и отдаётся самим приложением из `public/monaco` (его копирует `scripts/copy-monaco.mjs` перед `dev` и `build`), без CDN: редактор работает офлайн и в Docker.
- Запросы разбора при вводе — с дебаунсом и отменой (`AbortController`).
- Цель: интерактивность (`INP`) < 200 мс при 150 узлах на холсте.

## 9. Тестирование интерфейса

- Vitest + Testing Library: хуки (`useRunEvents`), хранилища, формы инспектора, преобразование `FlowGraph → nodes/edges`.
- Playwright E2E: пути демо — импорт примера → граф → правка блока → код обновился → запуск → тесты зелёные; негативный контроль gate (раздел 10 в [07](07-behavior-verification.md#10-контрольный-список-доказательства-для-демо)).
- Скриншот-тест ключевых экранов (визуальная проверка соответствия макету вручную на S10).
