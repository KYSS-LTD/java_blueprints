# 13. Отчёт приёмки (S10.1)

Сверка с [матрицей ТЗ](plan/README.md#матрица-покрытия-тз) и критериями A1–A9 ([10 § 4](10-quality-and-testing.md#4-приёмочные-критерии-mvp-definition-of-done-проекта)). Состояние: ✅ сделано и проверено, ⚠️ сделано частично или проверено не полностью, ❌ нет. «Доказательство» — где это проверяется (тест, скрипт, отчёт).

Проверено на Windows 11, Python 3.14, JDK 17 (Eclipse Temurin); JDK 21, Linux и Docker в среде разработки недоступны.

## 3. Список дефектов и ограничений

| № | Приоритет | Описание | Решение |
|---|---|---|---|
| D-1 | средний | Оценка Big O завышена у слоёных монолитов (`O(n^8)` у калькулятора выражений): единый символ `n` перемножается по слоям вызовов | уверенность помечена `heuristic`, подтверждается «Проверить»; в `SOLUTION.md` — ограничение |
| D-2 | средний | Ускорение ≥ 2× на `demo-orders` не достигается безопасными автоисправлениями: `mergeDuplicates` — группировка по составному ключу с накоплением (аналог `OPT-09`) | оставлено как рекомендация (`PERF-01`), `OPT-01` применим только к вложенным циклам с равенством одного ключа; перенести в план после сдачи |
| D-3 | низкий | `OPT-09`, `OPT-10`, `REF-03` не реализованы; каталог типов JDK неполный | находки остаются рекомендациями; при неопределённости типа исправление не предлагается |
| D-4 | средний | Нет Playwright E2E (`demo_full_path`, `code_to_graph`, `undo_redo`, `negative_control`, `diagnostics`, `optimize_all`, `decompose`) | эквивалентные сценарии проходят в интеграционных тестах API и Vitest; ручная проверка в браузере |
| D-5 | средний | Docker-образы не собирались, JDK 21 и Linux не проверялись | CI (`.github/workflows/ci.yml`) прогоняет JDK 21 на Ubuntu; ручной прогон на чистой машине перед демо |
| D-6 | низкий | Два теста backend требуют JDK 21+ (`test_jdk.py`, `/health` с установленным JDK) и падают на JDK 17 по замыслу | без JDK 21 помечены как ожидаемые |
| D-7 | низкий | На холсте при 1280×720 и вложенных циклах схема подгоняется под ширину (масштаб ≈ 20%) | масштаб и перемещение доступны; панели меняют размер |
| D-8 | низкий | Три теста Vitest изредка падают по времени под нагрузкой (общий `testTimeout` 20 с) | повторный запуск зелёный |

Исправленные в ходе приёмки дефекты (S10.2): бенчмарк измерял рост на случайном вводе, который программа отвергала (`k ≈ 1` у всех программ) — теперь ввод строится из рабочих сценариев проекта; `GET /projects/{id}` не возвращал счётчики gate (значок «поведение совпадает (11/11)» показывал только статус); бенчмарк не набирал точек выше шума и «до» оптимизации выглядело линейным; демо-проект создавался без эталона.
