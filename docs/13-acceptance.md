Состояние: ✅ сделано и проверено, ⚠️ сделано частично или проверено не полностью, ❌ нет. «Доказательство» — где это проверяется (тест, скрипт, отчёт).

## 3. Список дефектов и ограничений

| № | Приоритет | Описание | Решение |
|---|---|---|---|
| D-1 | средний | Оценка Big O завышена у слоёных монолитов (`O(n^8)` у калькулятора выражений): единый символ `n` перемножается по слоям вызовов | уверенность помечена `heuristic`, подтверждается «Проверить»; в `SOLUTION.md` — ограничение |
| D-2 | средний | Измеренное время `demo-orders` после оптимизации не уменьшается (≈ 1,0×), хотя работа сокращается в 9,2×: на размерах, которые бенчмарк успевает пройти (до N = 8000), квадратичная часть (`findOrderById`, 32 млн вызовов геттера при N = 8000) занимает малую долю времени; для ≥ 2× по времени нужен ввод на порядки больше | отчёт оптимизации показывает оба показателя («блоков выполняется меньше в 9,2×» и «время программы ×0,9»); бенчмарк при желании можно запустить на больших N вручную |
| D-3 | низкий | `OPT-10`, `REF-03` не реализованы; каталог типов JDK неполный | находки остаются рекомендациями; при неопределённости типа исправление не предлагается |
| D-4 | закрыт | Playwright E2E (`demo_full_path`, `code_to_graph`, `undo_redo`, `negative_control`, `diagnostics`, `optimize_all`, `decompose`, `export`) написаны и проходят локально в Edge (`pnpm e2e`, `E2E_CHANNEL=msedge`); job `e2e` в CI запускает их на `docker compose` | запуск в CI и на Chromium не проверялся |
| D-5 | закрыт | Docker-образы, JDK 21 и Linux не проверялись | проверено в Docker (см. A8); нашли и исправили три дефекта (ниже). Остаётся только запуск GitHub Actions (`.github/workflows/ci.yml`) |
| D-6 | низкий | Два теста backend требуют JDK 21+ (`test_jdk.py`, `/health` с установленным JDK) и падают на JDK 17 по замыслу | без JDK 21 помечены как ожидаемые |
| D-7 | низкий | На холсте при 1280×720 и вложенных циклах схема подгоняется под ширину (масштаб ≈ 20%) | масштаб и перемещение доступны; панели меняют размер |
| D-8 | низкий | Три теста Vitest изредка падают по времени под нагрузкой (общий `testTimeout` 20 с) | повторный запуск зелёный |

Прочность на чужом коде (S10.2): 120 крупнейших файлов JDK (`java.base`: `util`, `lang`, `io`, `text`, `time`; 213 900 строк, 7772 метода) проходят весь конвейер без падений: блок-схемы всех методов (id уникальны, блоки достижимы, ни один оператор не потерян, запасных блоков «Код» — 4), анализ (3080 находок), предпросмотр каждого доступного исправления (1344 применимы, результат всегда разбирается) и инвариант I2 на 3211 заменах блоков (`scripts/jdk_sweep.py` → `reports/jdk_sweep.md`; нужен `src.zip` из JDK). Прогон нашёл и исправил три дефекта: `FIX-02` комментировал закрывающую скобку в `catch (E e) { /* … */ }` на одной строке; `REF-01/REF-02` теряли тип varargs-параметра (`T... имя`); `CLEAN-01` перебирал весь класс на каждую находку (анализ файла с 242 находками: 8,4 с → 1,1 с). Результаты исправлений проверялись разбором, а не сборкой `javac`: файлы JDK по одному не компилируются.

Дефекты, найденные при проверке в Docker (S10.7): (1) в контейнере примеры не находились (путь к `samples` вычислялся как `/samples`, образ кладёт их в `/app/samples`), поэтому не создавался демо-проект и был пуст список примеров — в `Dockerfile` задан `JB_SAMPLES_DIR`; (2) гонка в SSE: запуск помечался завершённым до публикации `result`, `status` и `done`, и подписчик, дочитавший к этому моменту, получал обрыв потока без итога — признак `finished` ставится после `done`, добавлен регрессионный тест; (3) тест `test_timeout_kills_the_whole_process_tree` запускал `sleep` по имени, а в чистом окружении запуска `PATH` содержит только каталог Java — теперь `/bin/sleep`.

Исправленные в ходе приёмки дефекты (S10.2): бенчмарк измерял рост на случайном вводе, который программа отвергала (`k ≈ 1` у всех программ) — теперь ввод строится из рабочих сценариев проекта; `GET /projects/{id}` не возвращал счётчики gate (значок «поведение совпадает (11/11)» показывал только статус); бенчмарк не набирал точек выше шума и «до» оптимизации выглядело линейным; демо-проект создавался без эталона.
